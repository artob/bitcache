# AGENTS.md — Bitcache (Rust)

Bitcache is a distributed content-addressable storage (CAS) system. Blobs are
immutable, identified by the BLAKE3 hash of their contents (`Id`).

## Workspace

Cargo workspace, `members = ["lib/*"]`, edition 2024, all code public domain
(each file starts with `// This is free and unencumbered software released
into the public domain.`).

- `lib/bitcache-core` — core types/traits: `Id`, `Blob`, `Repository` (async
  trait via native `-> impl Future + Send`; `DynRepository` generated by
  `dynosaur`), `PutOptions`, `CompactOptions`, `Compression`, `ListOptions`,
  `Config` (`.bitcache/config.toml`, feature `config`), `RepositoryError`.
  Runtime-agnostic: tokio is optional; re-exports `futures_util`, `tokio`.
- `lib/bitcache` — umbrella crate + CLI (`src/main.rs`, bin needs
  `--features cli`). Re-exports `bitcache_core::*`.
- `lib/bitcache-fs` — filesystem backend (`FsRepository`), the most developed
  backend. Others: `-heap`, `-git`, `-turso` (sqlite), `-valkey` (redis),
  `-opendal`, `-iroh` (mostly thinner).

`README.md` is generated using Readmer (`readmer`) from Liquid Markdown
templates in `../.config/readmer/` and `../data/readmer/`. The `Makefile`
knows how to rebuild it. Avoid touching `README.md` or its input templates,
focus on changes to the actual code and inline docs to go with it.

## Build / test

```sh
cargo build --workspace                 # everything
cargo test -p bitcache-fs               # fs backend tests (tests/repository.rs)
cargo test -p bitcache-core --features config
cargo build -p bitcache                 # IMPORTANT: also build standalone;
cargo build -p bitcache-fs              # workspace feature-unification hides
                                        # non-tokio / feature-gated breakage
cargo build -p bitcache --bin bitcache --features cli   # the CLI binary
```

Smoke-test CLI: run `target/debug/bitcache` (init/put/list/get/compact/clear
--force) in a scratch dir; repo lives in `./.bitcache/` (or `$BITCACHE_URL`).

## Conventions

- Crates are `#![no_std]` + `extern crate alloc/std` behind `alloc`/`std`
  features; write `std::format!`, `std::vec![`, `String`/`Vec` imported from
  `std::string`/`std::vec`. Gate tokio-dependent code with
  `#[cfg(feature = "tokio")]` and provide non-tokio fallbacks.
- `rustfmt.toml`: `match_block_trailing_comma = true` (i.e. `},` after match
  arm blocks). Run `cargo fmt`.
- Errors: backends use `RepositoryError` (thiserror; `From<io::Error>`).
- Every public item gets a doc comment; comments explain *why* (concurrency,
  atomicity, fallback rationale).
- New `Repository` trait methods should have default impls (all backends +
  dynosaur must still compile). Method-level `where Self::Error:
  From<std::io::Error>` is OK.

## `bitcache-fs` specifics

On-disk layout (no backwards compat guaranteed yet):

```
.bitcache/
├── config.toml        # written by CLI init, never overwritten
├── .gitattributes     # "blobs/** binary" (future: LFS/Xet filter)
├── .gitignore         # ".tmp-*"
└── blobs/<2-hex-shard>/<full-64-hex-id>[.xz]   # shards created lazily
```

- Access is capability-scoped via `cap_std::fs_utf8::Dir`; avoid ambient
  paths (Windows keeps a canonical path fallback for ADS metadata).
- Blob files are read-only (0444); extended metadata (expires, media-type,
  created/updated) via xattrs (Unix) / NTFS ADS (Windows), see
  `file_metadata.rs`. Expired blobs are logically absent but physically
  present until removed.
- Writes: stream to root-level `.tmp-put-<pid>-<seq>`, then publish via
  hard-link (never replaces an existing blob; re-insert refreshes metadata).
  With `Compression::None` on APFS/Btrfs/XFS, `put_from_path` reflinks
  (`ioctl_ficlone`/`fclonefileat`) then hashes the clone; falls back
  silently on EXDEV/unsupported.
- Compression: `none | xz(:fast) | xz:best`; backend default for put is
  XzFast; `compact_with_options` recompresses toward the target (`xz:best`
  also rewrites fastest-preset xz, detected by dictionary size).
- Iteration: all enumeration goes through `DirCursor` (a `Stream` of
  `(Id, BlobEncoding)`), one sorted shard batch in memory at a time, global
  ID order; keep it that way for 1M–100M blob scalability.
- `clear` is atomic: rename `blobs/` → `.tmp-clear-<pid>-<seq>`, recreate
  `blobs/`, delete offline. `compact` also sweeps orphaned `.tmp-*`
  (clear-dirs always; put-files only if >1h old).

## Config (`.bitcache/config.toml`)

`[bitcache]` requires `version = 0` (crate major) and `hashing = "blake3"`;
optional `capacity = "100M"` (K/M/B/T suffix), `encoding = hex|base58`.
Per-command sections mirror CLI flags (`[bitcache.put]`/`[bitcache.compact]`
`compress = ...`); `[bitcache.remote.NAME] url = ...` names remotes for
push/pull/sync. CLI precedence: flag > config > default (put=none,
compact=xz). Unknown hashing/newer version must fail with `EX_CONFIG`.
